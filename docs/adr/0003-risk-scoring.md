# 0003. 위험도 계산 방식

- 상태: Proposed
- 날짜: 2026-10-31

## 맥락

앱의 핵심은 "이 길이 얼마나 위험한가"를 하나의 점수로 만들어 경로를 고르고 경고하는 것이다. 지금 날씨가 아니라 **그 구간을 지나게 될 시각**의 날씨가 중요하다. 또 예보는 5km 격자 단위라 실제 길 위의 상황과 다를 수 있다.

NaviHelper는 경로선 좌표를 주지 않는다 (ADR 0005). 그래서 실제 주행 모드에서는 경로 전체의 구간별 점수를 계산할 수 없다.

## 결정

### 구간 점수 (0~1)

```
구간점수 = (0.35×날씨 + 0.20×특보 + 0.30×취약지점 + 0.15×결빙) × 차량보정
경로점수 = Σ(구간점수 × 구간 통과 시간) ÷ 전체 소요 시간
```

- 구간: 경로를 약 1km씩 나눈 것. 각 구간을 지나는 **예상 시각의 예보**를 쓴다 (기상청 초단기예보).
- 날씨: 시간당 강수량·적설. 특보: 호우·대설 특보 지역 여부. 취약지점: 지하차도·하천변 도로·과거 침수 지점. 결빙: 결빙 취약구간 + 기온 영하.
- **가중치는 임시값**이다. 시나리오와 과거 사례로 조정한다.

### 차량 보정 (×0.8 ~ ×1.5)

- 와이퍼: 최고 단계면 비가 예보보다 강하다고 보고 올리고, 예보는 비인데 꺼져 있으면 내린다.
- 외기온도: 영하면 결빙 점수를 바로 반영한다.
- 차종: 세단 / SUV / 전기차 3단계로 침수 위험 기준을 다르게 잡는다 (CarInfo로 확인되는 값에 따라).

### 추천 규칙

1. 통제·사고 구간이 있는 경로는 제외한다.
2. 소요 시간이 최단 대비 +20% 이내인 경로 중 경로점수가 가장 낮은 경로를 추천한다.
3. 모든 경로가 0.6 이상이면 출발 연기나 휴식 장소를 제안한다.

### 모드별 적용

| 모드 | 계산 범위 |
| --- | --- |
| 시나리오 모드 | 시나리오 파일의 경로선으로 **경로 전체 구간 점수**와 후보 경로 비교 |
| 실제 주행 모드 | 경로선이 없으므로 **현재 위치 주변·목적지 주변·특보 지역**의 위험과, 기본 내비가 주는 교통 이벤트(사고·공사·재난)·주의 지점(미끄러운 도로·안개 등)으로 판단. 후보 경로 비교는 하지 않는다 |

### 구현

- `risk/`에 SDK·네트워크와 분리된 순수 Kotlin으로 만들고 단위 테스트를 붙인다.

## 검토한 대안

- 지금 위치의 날씨만 보기 — 단순하지만, 20~30분 뒤 지날 구간의 비를 놓친다.
- 기계학습 모델 — 학습 데이터와 시간이 없다.

## 결과

- 점수 하나로 경로 비교·경고·진행 막대 표시를 모두 할 수 있다.
- 실제 주행 모드에서는 경로 비교가 안 되는 약점이 있다. 심사·시연은 시나리오 모드로 보여 준다.
- 다시 볼 조건: 가중치가 시나리오에서 어색한 결과를 내면, 또는 경로선 좌표를 얻을 방법이 생기면.
