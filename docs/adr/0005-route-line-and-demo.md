# 0005. 경로선 표시와 시연 방식 (C안)

- 상태: Proposed
- 날짜: 2026-10-31

## 맥락

10/30 Pleos 에뮬레이터에서 확인한 사실 (PLE-12):

1. NaviHelper는 **경로선 좌표를 주지 않는다.** 경로는 "전체 길이 중 몇 %"라는 비율로만 표현된다.
2. 에뮬레이터 GNSS가 NMEA 문장의 체크섬을 항상 `*47`로 보낸다. 기본 내비(`GpsLocationSource`)는 이를 `NMEA checksum mismatch`로 모두 버려서 **기본 내비 위치가 움직이지 않는다.** 올바른 체크섬으로 `geo nmea`를 보내도 에뮬레이터가 다시 `*47`을 붙인다.
3. 반면 **FusedLocation은 안드로이드 시스템 위치를 따라서 `adb emu geo fix`로 움직인다.**
4. 에뮬레이터에는 모의 주행 기능이 없고, Virtual Console에도 위치·경로 주행 기능이 없다.

공모전 문의는 받지 않아서(10/31) 2번을 고칠 방법을 물을 수 없다.

## 결정

| 모드 | 경로선 | 내 위치 | 회전 안내·남은 거리 |
| --- | --- | --- | --- |
| **실제 주행** | 그리지 않는다. 세로 진행 막대(회전 지점·막힘 구간·위험 구간)로 대신한다 | FusedLocation | NaviHelper |
| **시나리오 (시연)** | 시나리오 파일에 미리 넣은 경로선을 그린다 | FusedLocation (GPS 조작으로 실제로 움직임) | 시나리오 파일 |

- 시나리오 파일은 NaviHelper가 주는 값과 **같은 모양**으로 화면 상태 모델에 넘긴다. 화면은 모드를 몰라도 된다.
- 시나리오의 경로선 좌표는 개발할 때 미리 만들어 파일에 넣는다. 앱에 외부 길찾기를 넣지 않는다.
- GPS 경로 재생 스크립트로 시나리오 경로를 따라 에뮬레이터 위치를 움직인다. 그러면 위험 지점 반경 알림은 **실제로** 울린다.
- 첫 시나리오: "도심 폭우 퇴근길" (PLE-15).

## 검토한 대안

- A: 경로선 없이만 — 정직하지만 시연 화면에서 "어느 길로 가는지"가 안 보인다.
- B: 외부 길찾기로 경로선만 받기 — 기본 내비 경로와 어긋날 수 있고, 외부 서비스 도입이 필요하다.
- GPS 조작으로 기본 내비를 움직이기 — 에뮬레이터 버그로 불가능했다.

## 결과

- 시연 영상은 시안처럼 경로선이 있는 화면으로 만들 수 있다. 위치 이동과 위험 경고는 진짜로 동작한다.
- 회전 안내 숫자는 시연에서 미리 준비한 값이다. 기획서·PT에서 "에뮬레이터 제약으로 시나리오 재생"임을 밝힌다.
- 실제 주행 모드는 실차가 없어 끝까지 확인하지 못한다.
- 다시 볼 조건: 에뮬레이터 GPS 버그가 고쳐지면(새 에뮬레이터 버전), 또는 경로선 좌표를 얻을 방법이 생기면.
