# MVP: 1차 제출

현대자동차그룹 차량용 앱 개발 공모전 일반 부문에 낼 앱의 범위와 일정을 정리한 문서다. 결정의 이유는 `docs/adr/`에 따로 적는다. 할 일은 Linear(팀 Pleos, 프로젝트 "1차 제출")에서 관리한다.

## 무엇을 만드나

비, 눈, 침수, 결빙, 도로 통제 같은 위험을 미리 보여 주고 안전한 길로 가도록 돕는 Pleos Connect 앱이다. 앱 이름은 ETA다.

기본 내비와 별개인 우리 내비다. 목적지 검색(카카오 로컬), 경로 계산(OSRM), 후보 경로 위험도 비교, 지도 위 경로선, 회전 안내와 음성, 경로 이탈 시 재탐색까지 앱이 한다(ADR 0007). 지도는 MapLibre로 그린다.

1차 제출의 목표는 에뮬레이터에서 "도심 폭우 퇴근길" 시나리오를 처음부터 끝까지 보여 주는 것이다. 목적지를 검색해 후보 경로를 위험도로 비교하고, 안전한 경로로 안내를 받다가, 위험 지점에 가까워지면 음성 경고와 우회 제안을 받는 장면을 시연 영상과 APK로 낸다.

## 심사 기준별로 보여 줄 것

- 차량 특화성: 와이퍼, 외기온도, 안개등 상태로 예보를 보정한다. 차종에 따라 침수 기준을 다르게 둔다. 정차 중에는 출발 전 브리핑을, 주행 중에는 음성 안내만 한다.
- 창의성: 지하차도나 하천변 도로처럼 들어가 보기 전에는 알 수 없는 위험을, 그 구간을 지날 시각의 예보로 미리 알려 준다. 동승자가 위험 정보를 대신 확인할 수 있게 한다.
- 기술 활용성: FusedLocation(내 위치·반경 알림), Vehicle(와이퍼·외기온도·차속), TextToSpeech(안내 음성)를 핵심 기능에 쓴다. NaviHelper는 경로 계산에 쓰지 않는다(ADR 0007).
- 사업성: 침수 취약 지역을 지나 출퇴근하는 운전자가 첫 대상이다. 평소에는 결빙, 안개, 통제 안내로 계속 쓰게 하고, 물류 차량과 보험 쪽으로 넓힐 수 있다.

## 1차 제출까지 할 것

- [ ] 에뮬레이터에서 앱 실행
- [ ] 우리 앱 검색창에서 목적지 검색
- [ ] 후보 경로를 계산하고 위험도로 비교해 가장 안전한 경로를 기본 선택
- [ ] 안내 화면에 경로선, 다음 회전, 남은 거리, 도착 시각 표시와 경로 이탈 시 재탐색
- [ ] 침수·결빙·통제 지점을 지도와 세로 진행 막대에 표시
- [ ] 위험 지점에 가까워지면 음성 경고, 새 위험이 생기면 우회 제안
- [ ] 정차 중 시동을 켜면 출발 전 브리핑
- [ ] 와이퍼 단계와 차종을 위험도에 반영
- [ ] "도심 폭우 퇴근길" 시나리오 재생
- [ ] release APK 빌드

## 에뮬레이터에서 알게 된 제약

아래는 기본 내비를 쓰던 때(ADR 0004·0005) 확인한 내용이다. 지금은 경로 계산을 앱이 하므로 실제 주행 안내는 FusedLocation 위치로 움직인다.


- NaviHelper는 경로선 좌표를 주지 않는다.
- 에뮬레이터에서 위치를 바꿔도 기본 내비는 움직이지 않는다. 에뮬레이터가 보내는 GPS 문장의 체크섬이 틀려서 기본 내비가 버린다. FusedLocation은 정상적으로 따라온다.
- 에뮬레이터 기본 내비에는 배경 지도가 나오지 않는다.
- Pleos 콘솔에서 FusedLocation, TextToSpeech, SpeechToText, Vehicle Control은 아직 준비 중으로 나온다. 에뮬레이터에서는 Vehicle Control만 막혀 있다.
