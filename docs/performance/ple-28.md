# PLE-28 안내 지도 성능 확인

2026-11-05, 실행 중인 Pleos API 34 에뮬레이터(`emulator-5554`, 2560×1440, RAM 약 4GB, user 10)에서 확인했다. 차량은 P 상태이며 왼쪽 차량 패널도 보이는 상태다. 에뮬레이터나 차량 상태 설정은 바꾸지 않았다.

## 구현

- `MapView.setMaximumFps(30)`으로 지도 렌더링 상한을 설정한다. 위치·카메라 갱신도 화면 시각에 맞춰 약 30회/초로 제한한다. 늦은 프레임은 몰아서 처리하지 않고 현재 재생 시각의 위치를 그린다.
- PLE-26에서 만든 경로 보간을 유지한다. 카메라 애니메이션을 매초 추가하지 않으므로 중첩되는 애니메이션도 없다.
- 안내의 운전자 시점이고 줌이 15 이상일 때만 3D 건물을 표시한다. 지도 드래그·확대·축소와 관성 이동 중에는 숨기고, 멈추면 표시 조건을 다시 확인한다.
- 건물의 높이·경로 주변 보호 거리 계산과 표시 전환을 분리했다. 표시 전환에는 `fill-extrusion-opacity`를 사용해 건물 레이아웃을 다시 만들지 않는다. 전환 애니메이션 없이 0으로 바꾸며, 사용 중인 렌더러는 opacity가 0이면 돌출 건물 그리기를 생략한다.
- 지도를 직접 조작하면 자동 카메라 추적을 멈춘다. 내 위치 표식은 계속 이동하며, **내 위치로**를 누르면 자동 추적과 가까운 시점으로 복귀한다.
- 기존 90m 경로·위험 지점 여백, 건물 최대 높이 60m, 표시할 때의 불투명도 0.45와 안내 레이어 순서는 유지한다.

## CPU 측정

비교 기준은 `main`의 `feed28b7cadf75527952f665dd25df3d8e64a73c`를 빌드한 debug APK다. 같은 에뮬레이터에 기준 APK와 변경 APK를 차례로 덮어 설치했다. 앱 데이터나 타일 캐시는 지우지 않았다. 아래 수치는 **한 코어를 100%로 보는 프로세스 CPU 값**이다. 전체 CPU 점유율과 같지 않다.

| 조건 | 변경 전 앱 CPU | 변경 후 앱 CPU | 결과 |
| --- | ---: | ---: | --- |
| 일시정지 후 지도 반복 드래그 | 100.08% | 37.30% | 약 62.7% 감소 |
| 가까운 3D 운전자 시점, 1배 자동 재생 | 104.53% | 103.65% | 뚜렷한 감소 없음 |

변경 전은 조건별 2회, 변경 후는 최종 APK로 조건별 1회 측정했다. 매회 1초 간격으로 25개를 수집하고 초기 5개를 버린 20개를 평균했다. 변경 전 드래그 각 회 평균은 99.65%, 100.50%였고, 재생은 104.55%, 104.50%였다. 측정 중 화면 녹화는 하지 않았다.

같이 수집한 차량 패널(`ai.umos.drivingview`) CPU는 드래그 전후 102.10% → 95.35%, 자동 재생 전후 102.98% → 102.25%였다. 시스템 화면의 부하는 여전히 남아 있으며, 이 작업의 개선 수치를 자동 재생 전체나 실기기에 일반화할 수 없다. 30fps는 상한이며 에뮬레이터에서 30fps를 항상 달성한다는 뜻은 아니다.

원본 `top` 출력과 초기 5개를 제외한 표본·평균은 [ple-28/](./ple-28/)에 함께 남겼다.

### 같은 조건으로 다시 재기

1. 시연 모드 → 안전 경로로 출발 → **처음으로** → **내 위치로**를 누른다. 재생은 멈춘 상태이고 운전자 시점이다.
2. 타일을 불러올 시간을 3초 준 뒤 다음 명령으로 앱과 차량 패널을 같이 측정한다. 두 번째 터미널에서는 300px 드래그를 1초씩 좌우로 총 24회 반복한다. 좌표는 2560×1440 화면의 앱 지도 영역 기준이다.

```bash
adb shell top -b -d 1 -n 25 -p "$(adb shell pidof com.example.pleosproj),$(adb shell pidof ai.umos.drivingview)" > drag.top.txt
```

```bash
for i in {1..12}; do
  adb shell input swipe 1700 780 2000 780 1000
  adb shell input swipe 2000 780 1700 780 1000
done
```

3. 자동 재생 측정은 다시 **처음으로** → **내 위치로**를 누르고 3초 기다린 후 **재생**을 누른다. 드래그 없이 같은 `top` 명령으로 측정한다.
4. 첫 5개 표본을 제외하고 각 프로세스 행의 `%CPU`를 평균한다. 측정 도중 다른 조작이나 녹화를 하지 않는다.

## 기능 확인

- 빌드와 단위 테스트 80개를 통과했다. 추가한 4개 테스트는 60·90·120Hz에서 30회/초 갱신, 작은 VSync 시각 오차에서도 일정한 간격, 지연 후 중복 프레임 방지, 줌·조작·화면에 따른 건물 표시 조건을 확인한다.
- 에뮬레이터에서 드래그 중 건물 숨김과 정지 후 복귀, **내 위치로** 추적 재개, **위에서 보기**의 낮은 줌·2D 표시, 운전자 시점 복귀를 확인했다. 운전자 시점의 줌 15 경계 조건은 단위 테스트로 확인했다.
- 1·2·4배 재생, 일시정지, 처음으로를 확인했다. 4배 재생의 언주로 좌회전 전후를 녹화해 내 위치가 도로를 따라 이동하고 카메라가 이어서 회전하는지 확인했다.
- 실제 화면은 [스크린샷 폴더](../screenshots/ple-28/)에 남겼다. 원본 PNG는 `adb exec-out screencap -p`로 캡처했다. GIF는 실제 화면 녹화의 앱 영역을 잘라 용량을 줄인 10fps 미리보기이며, 앱의 실제 렌더링 프레임 측정 자료가 아니다.
