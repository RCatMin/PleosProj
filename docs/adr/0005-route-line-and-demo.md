# 0005. 경로선 표시와 시연 방식

- 상태: Proposed
- 날짜: 2026-10-31

## 맥락

에뮬레이터에서 확인해 보니 두 가지 문제가 있었다.

첫째, NaviHelper는 경로선 좌표를 주지 않는다. 경로는 전체 길이 중 몇 퍼센트 지점인지로만 표현된다.

둘째, 에뮬레이터에서 위치를 바꿔도 기본 내비가 움직이지 않는다. 에뮬레이터가 보내는 GPS 문장(NMEA)의 체크섬이 항상 같은 값이라 기본 내비가 이를 잘못된 데이터로 보고 버린다. 체크섬을 맞춰서 직접 보내도 에뮬레이터가 다시 바꿔 버린다. 에뮬레이터에는 모의 주행 기능도 없다.

반면 FusedLocation은 안드로이드 시스템 위치를 따라가기 때문에 `adb emu geo fix`로 바꾼 위치가 그대로 반영된다.

## 결정

실제 주행과 시연을 나눠서 다룬다.

실제 주행에서는 경로선을 그리지 않는다. 대신 세로 진행 막대에 회전 지점, 막힘 구간, 위험 구간을 표시한다. 회전 안내와 남은 거리는 NaviHelper에서, 내 위치는 FusedLocation에서 받는다.

시연에서는 시나리오 파일을 재생한다. 시나리오 파일에는 미리 만들어 둔 경로선과 시간 순서의 회전 안내, 위험 정보가 들어 있다. 재생기는 이 값을 NaviHelper가 주는 것과 같은 모양으로 화면에 넘기므로, 화면은 지금이 시연인지 실제 주행인지 몰라도 된다. 내 위치는 GPS 경로 재생 스크립트로 에뮬레이터 위치를 실제로 움직여서, 위험 지점 반경 알림이 진짜로 울리게 한다.

경로선 좌표는 개발할 때 미리 만들어 시나리오 파일에만 넣고, 앱에 외부 길찾기 기능을 넣지는 않는다. 첫 시나리오는 "도심 폭우 퇴근길"이다.

## 검토한 대안

경로선 없이 진행 막대만 쓰는 방법은 정직하지만, 시연 화면에서 어느 길로 가는지가 보이지 않는다.

외부 길찾기로 경로선만 받아 오는 방법은 기본 내비 경로와 어긋날 수 있고 외부 서비스를 들여야 한다.

GPS를 조작해 기본 내비를 움직이는 방법은 에뮬레이터 문제로 되지 않았다.

## 결과

시연 영상은 시안처럼 경로선이 있는 화면으로 만들 수 있다. 위치 이동과 위험 경고는 실제로 동작한다.

회전 안내 숫자는 시연에서 미리 준비한 값이므로, 기획서와 발표에서 에뮬레이터 제약 때문에 시나리오로 재생했다고 밝힌다. 실제 주행 모드는 실차가 없어 끝까지 확인하지 못한다.

에뮬레이터 GPS 문제가 고쳐지거나 경로선 좌표를 얻을 방법이 생기면 다시 정한다.
