# PLE-30 실제 주행 화면 연결

앱 안에서 목적지 검색 → 경로 비교 → 선택한 경로의 출발 전 브리핑 → 안내 → 종료·도착까지 이어집니다. 실제 주행은 카카오 로컬 검색과 OSRM 경로를 사용하고, `시연 모드`는 기존 도심 폭우 퇴근길 시나리오를 재생합니다.

## 연결부

| 화면 동작 | 개발 연결부 |
| --- | --- |
| 이름·주소 검색 | `PlaceSearch.create().search(query, near)`를 IO 스레드에서 호출합니다. 결과와 최근 목적지는 `ui/state/Place`를 그대로 씁니다. |
| 최근 목적지 | `RecentPlaces.list()`로 읽고 목적지를 선택할 때 `add(place)`로 저장합니다. 저장된 기록에 없는 거리는 표시하지 않습니다. |
| 후보 경로 | `GuidanceSession.plan(place)` 결과의 `compare`를 표시합니다. 로딩·계산 실패·재시도를 처리합니다. |
| 출발 전 브리핑 | 선택한 후보의 시간·위험 단계·요약과 안내 엔진의 날씨 카드로 표시합니다. `GuidanceVoice.speakBriefing`으로 읽습니다. |
| 안내 시작·갱신 | 선택한 id로 `startGuidance`를 호출하고 `onState`로 경로선·내 위치·회전·거리·도착 시각을 갱신합니다. |
| 우회 | 현재 알림의 `hazardId`로 `acceptDetour`를 호출합니다. `Detoured`·`DetourFailed` 결과를 표시합니다. |
| 재탐색·도착 | `Rerouted`는 새 경로 안내와 메시지로, `Arrived`와 null 상태는 도착 메시지와 검색 화면 복귀로 처리합니다. |
| 음성·종료 | 안내 세션의 `voiceEnabled`, `endGuidance`, `stop`에 연결합니다. 주행 중 음성은 세션이, 출발 전 브리핑은 화면의 음성 연결부가 맡습니다. |

UI 연결은 `ui/navigation/NavigationSource.kt`, 화면 선택과 비동기 요청 수명 관리는 `NavigationFlowController.kt`, Compose 화면 조립은 `NavigationFlowHost.kt`에 있습니다. 예시 전용 PlaceExample과 검색·도착 상태 전환 버튼을 제거했습니다.

## 화면 동작

- 정차를 확인한 경우에만 검색·목적지·경로 선택을 허용합니다. 주행 또는 정차 확인 불가 상태가 되면 키보드를 닫고 검색 요청을 취소합니다. 상태를 판단할 차량 신호를 변경하지 않습니다.
- 검색·경로 요청의 이전 응답이 뒤늦게 도착해도 다른 화면이나 새 요청의 결과를 덮지 않습니다.
- 검색 서비스 설정 문제·사용량 초과·연결 실패를 구분합니다. 연결 실패에는 재시도를 제공합니다.
- 통제로 제외된 경로는 선택하지 못하게 하고, 추천 경로를 기본 선택합니다. 고른 후보의 브리핑과 id를 그대로 안내 세션에 전달합니다.
- 날씨 조회 실패를 알 수 있는 경우 브리핑·비교·안내에 이를 표시하고, 대체 날씨 값을 실제 관측 정보처럼 표시하지 않습니다.
- 예상 시간에는 실시간 교통이 반영되지 않음을 표시합니다.
- 같은 위험 알림을 확인한 뒤 매초 다시 띄우지 않으며, 단계나 문구가 바뀌면 다시 표시합니다.
- 실제 안내 중 시연 모드를 선택하면 전환을 확인하고 기존 세션을 종료합니다. 화면을 떠나거나 권한이 바뀌면 해당 세션을 종료하고, 다음 진입 때 새 세션을 만듭니다. 앱을 다시 열면 목적지를 다시 선택해 안내를 시작합니다.

## 에뮬레이터 검증

에뮬레이터는 사람이 Android Studio에서 켜고 끕니다. 기존 연결부 검증은 PR #25·#27·#28·#31에서 머지됐습니다(#31이 #30을 대체합니다).

1. 정차 상태에서 목적지 `삼성역`을 입력하고 검색합니다. 결과의 `삼성역 2호선`을 선택하면 후보 경로가 표시됩니다.
2. 경로를 선택하고 `출발 전 브리핑`에서 시간·위험 요약을 확인한 뒤 `안전 경로로 출발`을 누릅니다.
3. 디버그 APK는 안내 시작 때 **화면에서 고른 경로선**을 앱 내부 `files/route.json`에 저장합니다. 다음 명령으로 그 경로를 따라 GPS를 움직일 수 있습니다.

```bash
python3 scripts/replay_route.py --speed-kmh 80 --user 10
```

4. 내 위치·회전·남은 거리 변화, 음성 켜기·끄기, 종료 확인·취소, 도착 후 검색 화면 복귀를 확인합니다.
5. `시연 모드`에서 브리핑·회전·위험 음성이 나오고, 실제 주행 상태와 섞이지 않는지 확인합니다.

화면 없이 엔진만 확인할 때는 `guide_start`도 사용할 수 있습니다. 이 디버그 세션을 실행했다면 `guide_stop`으로 끝낸 후 앱 화면에서 안내를 시작합니다.

```bash
adb shell am broadcast --user current -n com.example.pleosproj/.app.NaviProbeReceiver --es cmd guide_start
adb shell am broadcast --user current -n com.example.pleosproj/.app.NaviProbeReceiver --es cmd guide_stop
```

키는 Git 제외 로컬 설정으로만 제공하며, 스크린샷·PR·커밋에 키 값과 APK를 올리지 않습니다.

## 검증 결과

2026년 11월 9일 실제 선택 경로를 GPS로 끝까지 재생해 위치·회전·남은 거리 갱신과 자동 도착·검색 화면 복귀를 확인했습니다. 수동 종료·취소, 실제 안내와 시연의 음성 켜기·끄기, 시연 초기 브리핑·회전·위험 경고도 화면과 SDK 발화 로그로 확인했습니다. [화면별 캡처와 검증 기록](screenshots/ple-30/README.md)에 결과를 정리했습니다.

경로 이탈 상태를 유지한 뒤 자동 재탐색을 실행해 새 경로선·회전·남은 거리와 재탐색 메시지가 실제 화면에 반영되는 것도 추가 확인했습니다.
