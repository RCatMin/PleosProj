# PLE-46 경로 예보·거리별 날씨·시설 표시

## 연결

- 경로 비교의 선택한 후보에서 `RouteCandidate.forecast`를 그대로 읽습니다. 각 지점의 이름·거리·통과 시각·날씨를 표시하며, 날씨가 null이면 ‘예보 없음’으로 표시합니다. 비어 있는 목록은 ‘경로 예보 정보 없음’으로 구분합니다.
- `RouteCompareState.forecastBasis`가 있으면 표시하고, 없으면 근거 줄을 숨깁니다. 화면에서 정확도 등급이나 통과 시각을 계산하지 않습니다.
- 안내의 지금·10km 앞·20km 앞은 전달된 `WeatherCard.label`로 구분합니다. ‘목적지’ 또는 ‘10분 뒤’ 날씨를 거리 기준 카드로 바꾸지 않습니다. 목적지와 같거나 더 먼 거리의 예보는 숨기고 ‘정보 없음’으로 표시합니다.
- 시설은 회전 안내에서 추정하지 않고 `GuidanceState.facilities`의 종류·이름·남은 거리를 표시합니다. 목록이 비면 카드 전체를 숨깁니다. 시연용 성남IC·쉼터 고정 예시도 제거했습니다.
- 브리핑은 전달된 날씨를 모두 표시합니다. 3장 이상이면 카드 높이를 줄여 지금·10km 앞·20km 앞·목적지 4장을 확인할 수 있게 했습니다. 작은 화면에서는 목록을 스크롤할 수 있습니다.

`ui/state/`, 데이터 계산·SDK·시나리오, 의존성·권한은 변경하지 않았습니다.

## 실행 확인

`assembleDebug`, `testDebugUnitTest` 158개, `installDebug`를 통과했습니다. 날짜는 2026-11-09이며 코드 커밋은 `d2dae05`입니다.

1. 성남시청의 검색 좌표로 에뮬레이터 위치를 지정하고 앱에서 `Yangju Station`을 검색해 실제 양주역 1호선을 선택했습니다. 카카오모빌리티와 기상청 결과를 사용했습니다.
2. 추천 길 51.9km에서 출발 16:40, 17.3km 지점 17:05, 34.6km 지점 17:31, 도착 17:57과 예보를 확인했습니다. 가장 짧은 길을 선택하면 44.1km, 14.7km·29.4km 지점과 도착 18:58의 해당 후보 값으로 바뀝니다.
3. 브리핑에서 지금·10km 앞·20km 앞·목적지 날씨 4장을 확인하고 안내를 시작했습니다.
4. `scripts/replay_route.py --speed-kmh 80 --user 10`으로 약 733m 이동했습니다. 성남IC 거리가 2.8km에서 2.1km로 줄고 쉼터·톨게이트 거리도 갱신됐습니다. 이 구간에서 기존 엔진의 재탐색도 한 차례 발생했으며 화면은 새 안내 상태를 표시했습니다.
5. 같은 선택 경로의 27km 부근부터 재생해 구리IC·구리휴게소를 확인했습니다. 더 이동한 캡처에서는 구리IC가 1.5km에서 1.1km로, 구리휴게소가 3.0km에서 2.6km로 줄었습니다. 먼 지점 검증에는 재생기의 `--from` 옵션을 사용했습니다.
6. 강남역 부근 → 삼성역의 3.8km 경로에서 10km·20km 앞은 ‘정보 없음’이고 시설 카드는 숨겨짐을 확인했습니다.
7. 겨울 시연의 후보별 예보·가정 날씨 근거와 안내의 눈·영하 표시를 확인했습니다. 미제공 거리별 날씨와 시설을 예시로 채우지 않습니다.

[스크린샷 목록](screenshots/ple-46/README.md)에 캡처를 정리했습니다. 위치 재생 프로세스는 모두 종료했으며 안내를 종료하고 시연 선택 목록에서 검증을 마쳤습니다. 에뮬레이터를 켜거나 끄지 않았습니다.

## 검사 범위

거리 기준 예보가 다른 순서로 들어오는 경우, 목적지·시간 기준 카드를 거리 기준으로 잘못 복제하는 경우, 남은 거리가 10km·20km 경계와 같거나 더 짧은 경우를 단위 테스트로 확인했습니다. 지점별 null 날씨 표시는 코드로 처리했으며 이번 실제 API 결과에는 null인 지점이 없어 실행 캡처로 확인하지 않았습니다.

겨울 위험 요약의 ‘강한 비’ 문구는 기존 개발 이슈 [PLE-47](https://linear.app/scsblog/issue/PLE-47) 범위입니다. 예보의 수집·누락 판정·재탐색 계산은 기존 연결부 결과를 표시합니다.
