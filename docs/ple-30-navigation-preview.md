# PLE-30 우리 내비 화면 흐름 예시

11월 6일 변경한 방향에 따라 목적지 검색 → 경로 비교 → 브리핑 → 안내 → 종료를 앱 안에서 확인하는 화면입니다. NaviHelper와 기존 LiveSession은 연결하지 않습니다. 경로 계산과 실제 안내 연결은 PLE-34·36·37에서 제공할 연결부를 기다립니다.

## 확인 방법

실행 중인 Pleos 에뮬레이터에 APK를 설치하고 앱을 엽니다. 에뮬레이터는 사람이 켜고 끕니다.

1. 차량이 정차한 상태에서 `삼성역 검색해 보기`를 누르거나 검색창에 `삼성역` 또는 `samsung`을 입력하고 검색합니다. 이름·주소·거리가 표시된 결과를 선택합니다. 최근 목적지를 선택해도 비교 화면으로 이어집니다.
2. 비교 화면에서 보라색으로 선택된 추천 경로와 통제로 제외된 경로를 확인합니다. 선택 가능한 다른 경로를 고른 뒤 `출발 전 브리핑`을 누릅니다.
3. 선택한 경로의 예상 시간·도착 시각·위험 요약을 확인하고 `안전 경로로 출발`을 누릅니다. `경로 비교 보기`로 돌아가도 선택은 유지됩니다.
4. 안내 화면에서 선택한 경로선·내 위치·회전·남은 거리를 확인합니다. `다음 안내 예시`는 같은 경로의 중간 위치 예시로 바뀝니다. 자동 주행이나 실제 GPS 입력은 아닙니다.
5. `다른 경로`로 비교를 열고 선택만 바꾼 후 뒤로 돌아오면, 진행 중이던 경로와 선택을 복원합니다. 새 경로의 브리핑을 거쳐 출발하면 그 경로로 안내 예시가 바뀝니다.
6. `안내 종료`를 누르고 확인하면 첫 검색 화면으로 돌아갑니다. `도착 예시`도 첫 화면으로 돌아오며 도착 메시지가 나옵니다.
7. `검색 상태 예시` 메뉴에서 빈 결과·검색 준비 안 됨·연결 실패·요청 한도 초과를 고르고 검색해 상태와 재시도 화면을 확인합니다. 모두 화면 검증용 예시입니다. 실제 네트워크 장애나 API 키 유무를 검사하지 않습니다.
8. `시연 모드`는 기존 도심 폭우 퇴근길 재생기로 들어갑니다. 첫 화면으로 돌아오면 검색 흐름을 새로 시작합니다. 재생 상태와 안내 음성은 두 흐름 사이에 공유하지 않습니다.

## 데이터와 입력 제한

- 목적지는 삼성역 한 곳이며 최근 목적지도 예시 목록입니다. 앱 재실행 후 기록을 저장하는 기능은 PLE-34에서 연결합니다.
- 경로·날씨·위험·회전은 기존 `rain-commute.json`을 읽습니다. 선택한 경로별로 브리핑과 안내 예시를 만듭니다. 실제 기상·교통 상황이 아닙니다.
- 정차 여부는 기존 `VehicleSignalReader`를 MainActivity에서 읽습니다. 정차가 확인된 경우에만 검색·목적지·경로 선택 입력을 열고, 확인 불가 또는 주행 상태가 되면 키보드를 닫고 검색 요청을 취소합니다. 차량 신호는 변경하지 않습니다.
- 지도는 기존 MapLibre 지도를 사용합니다. 새 검색·OSRM 네트워크 요청이나 NaviHelper 초기화를 하지 않습니다.

## 연결부를 받을 위치

`ui/navigation/NavigationExamples.kt`는 화면 검증 전용 공급자입니다. 여기의 `PlaceExample`과 `NavigationExampleSource`는 공유 상태 모델이나 확정된 제품 API가 아닙니다.

PLE-34·36·37의 API와 별도 승인된 `ui/state/` 모델이 확정되면 다음 부분을 교체합니다.

| 화면 입력·출력 | 연결할 기능 |
| --- | --- |
| 검색어, 결과 목록·오류, 최근 목적지 | PLE-34 검색·최근 목적지 |
| 목적지 선택, `RouteCompareState` | PLE-36 OSRM 후보 경로·위험도 비교 |
| 선택 경로로 출발, `GuidanceState`, 음성 설정, 종료·도착 | PLE-37 안내 세션 |
| 다른 경로·우회 요청 | PLE-36·37의 재탐색·회피 경로 |

GPS 이동, 자동 도착 판정, 경로 이탈 재탐색, 실제 위험 지점 회피는 이 예시 구현에 포함되지 않습니다. `다른 경로`와 우회 동작은 경로 비교 화면으로 이어지는 화면 동선까지입니다.

음성은 기존 `GuidanceVoice`를 호출하고 끄기·화면 이탈·시연 종료 시 자원을 해제합니다. 브리핑·첫 안내가 음성 초기화 전에 유실되는 문제는 PLE-32의 별도 수정이 필요합니다. 이 브랜치에서 임의 대기 시간을 넣어 우회하지 않습니다.
